01

Mac Enrollment Checker

Jamf MDM · ADE · macOS

Click each item as you check it. Click once for PASS ✓, twice for FAIL ✗, three times to clear. Generate a full incident report when done.

Phase 1 — Local Device Checks
Self Service app present in /Applications
If missing, Jamf enrollment never completed
ls /Applications | grep 'Self Service'
MDM profile in System Settings → Privacy & Security → Profiles
If no district profile listed, device is unmanaged
Jamf binary installed
If not present, device was never enrolled or was wiped
which jamf
Serial number confirmed in Apple School Manager
Get serial: system_profiler SPHardwareDataType — then verify in ASM/ADE console that it's assigned to your district
system_profiler SPHardwareDataType | grep Serial
Phase 2 — Network & Connectivity
Device can reach Jamf Pro server
Replace hostname with your district's Jamf URL
ping -c 3 [your-jamf-server]
Port 443 open to Jamf server
Jamf requires HTTPS (443). Blocked port = enrollment stall.
nc -zv [jamf-server] 443
Apple MDM push endpoints reachable
albert.apple.com · deviceenrollment.apple.com · mdmenrollment.apple.com
curl -I https://albert.apple.com
Phase 3 — Re-Enrollment Steps (if Phase 1 or 2 failed)
Attempted manual re-enroll
If binary present but profile missing, manual re-enroll may succeed
sudo jamf enroll
ADE assignment verified in Apple School Manager console
Device must be assigned to the correct MDM server in ASM before ADE re-enrollment will work
Re-ran Setup Assistant / Factory reset initiated
Last resort: System Settings → General → Transfer or Reset → Erase All Content. Confirm data is backed up first.
Network drive mapped after successful enrollment
Should auto-map via login script on enrollment. If not: check AD binding + user's home drive path in AD.
Device / User / Ticket # (optional — appears in report)
Checked: 0 / 10
